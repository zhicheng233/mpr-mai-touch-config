# 桌面配置工具 (software)

基于 Avalonia 11 (.NET 9) 的 maimai 触摸控制器桌面配置、测试与调优工具。

---

## 主要功能

- **34 键实时视窗**：动态渲染 SVG 光圈面板，高亮展示当前击键；可监听原生游戏 9 字节帧速率。
- **48 通道实时遥测**：直方图展示各通道 Filtered、Baseline、Drop 及触发阈值，支持选中通道查看波形曲线。
- **PCB 图形化映射编辑器**：按 4 块板卡 12 通道排布，支持键位拖拽互换、防冲突保护、自动学习（按 A1~E8 顺序按压标定）与快照历史回滚。
- **分板引导式校准**：选择 MPR121 板卡，采集静止噪声与多次轻触，联合求解逐键安全阈值；支持 RAM 试用、硬件验证、失败键重测及恢复原配置。
- **一键固件刷写**：集成 bossac，自动处理 1200bps 重启与固件烧录。
- **MCP 服务支持**：支持内置 HTTP 端点（默认 8477）和 `--mcp` 命令行模式，允许 AI 助手自动化读取并调参（详见 [Mcp/README.md](MaimaiTouchTool/Mcp/README.md)）。
- **多语言**：支持中英文无缝切换。

## 分板引导式灵敏度校准

1. 连接设备，先应用或放弃暂存修改，并解决本地/设备冲突。校准始终使用**已应用的键位映射**。
2. 在「校准」页勾选需要调整的 MPR121（0x5A–0x5D，可单选或多选），开始引导。未选板保持不变。
3. 松开面板等待预热及约 3 秒空闲采样。若最近窗口仍漂移，会用滚动窗口自动重采，最多额外等 6 秒；已恢复的旧异常不再永久否决整轮，持续异常也不会让其他键无限等待。随后每键先日常轻触 3 次，再正常触摸 2 次；每次保持约 0.3 秒，并完全松开。**松开后才增加计数**。
4. 查看候选预览。硬件触摸位或显著原始信号变化均可启动采集，不要求达到统一的「深度」。响应偏好只影响求解，不是计数门槛；信号计数也不是物理按压力。
5. 点「临时应用并验证」：候选配置只写 RAM。再次静置采样，每键轻触 3 次再连续轻触 5 次，结束后静置 1 秒；必须实测到每次硬件触发和释放，且没有空闲/邻键误触。
6. 验证失败时可「仅重测失败键」；已验证的漏触/误触证据会收紧下一轮的阈值上界/下界。无安全区间时明确报告，不通过截断配置值假装成功。重测后仍需再次验证。
7. 验证通过后点「确认采用已验证配置」，再到配置页点「保存」，才会写入 Flash 并同步本地 JSON。也可随时丢弃结果，恢复校准前配置。

阈值分别受每键的空闲偏置、噪声、实测串扰和最弱有效触摸约束，再按板联合计算基准与逐键偏移。未测全一块板时固定其基准，避免改变未测键；选择性采纳也会保持未选键的实际阈值，无法表达时拒绝应用。

### C 区弱信号校准

- C1/C2（小面积、长走线）自动使用单独策略，按键身份决定策略，改映射后仍读取该键的实际通道；A/B/D/E 区策略不变。
- 静置阶段分别记录差值波动与 filtered 的 P95−P5 噪声。普通键继续使用原余量；C 区使用 `max(1, filtered 噪声 / 2)` 作为额外余量，避免在绝对空闲上界之外，再将 baseline 跳格造成的差值波动重复扣除。按压深度仍取最弱有效按压，不抬高实测信号、不删除坏样本。
- C 区原始信号采集还要求 filtered 相对按压前静置参考实际下降至少 `max(4, 余量+1)`，持续至少 60 ms；仅 baseline 上跳不能计作按压，长按中 baseline 下移也不能自动拆成多次原始按压。此时间要求只用于校准采集，不改变游戏响应或固件去抖。
- 保留绝对空闲、串扰、释放残余和历史验证限制；触摸阈值仍以 4 为步长且最低为 8，释放阈值不会为零。真实 filtered 噪声过大或轻触与串扰重叠时仍报告无安全区间。
- 结果会注明「C 区弱信号」和独立 filtered 噪声。它只是候选，仍须「临时应用并验证」完成每键 8 次实际硬件触摸/释放及空闲检查，不能用原始信号替代硬件验证。修改前的校准结果请丢弃后重新采集；不会自动应用或保存，也无需重刷固件。

### 静止信号判定与时间曲线

- 「最近静止窗口仍在漂移」：最近约 3 秒窗口前后半段的差值中位数相差 >8。重新稳定后自动更新统计，不继续沿用开头的失败标记。
- 「静止时持续 / 反复触发」：静置期间硬件触摸连续 ≥90 ms，或至少 3 帧且占窗口 ≥10%。一帧闪亮不再直接否决；真实持续卡键与反复误触仍不允许通过验证。
- 孤立极值只作提示，不再用全窗口最大值−最小值直接判不稳定。噪声使用 P95−P5，静止上界使用 P95；持续噪声仍进入安全阈值约束，不能用这个改动绕过无安全区间或硬件验证。
- 校准页下方及独立的「信号曲线」页均可查看实时二维图。上图显示 filtered / baseline，下图显示差值、量化后的硬件触摸/释放阈值，底部色条显示硬件按下。横轴为相对最新样本的秒数，上下图分别自动缩放纵轴。
- 默认跟随校准目标；取消「跟随当前校准键」后可切换任意键，查看已保留的历史。最多保留 30 秒 / 1200 帧；冻结仅停止图表记录，不暂停校准。结束采集后保留曲线，新开流会清空；丢帧、无效芯片状态、映射改变不会被连成连续信号。普通调试开流也会记录，无需进入校准。

### 容易卡键时

- 候选阈值不仅考虑按下深度，还考虑空闲噪声及松手后的残留信号，为固件固定的 4 计数释放回差留出余量；合成触摸阈值不低于 8，禁止零硬件释放阈值。
- 如果旧配置让某键一直亮，但原始信号能随触摸正常起落，采集阶段可在信号回落并保持至少 600 ms 后识别硬件卡住，再用原始信号采集完整按下/松开动作。静止常亮本身不会算作一次按压，界面会注明旧配置出现卡键。
- 临时验证不允许这种兜底：每键先轻触 3 次、再按正常节奏连续轻触 5 次，不可提前结束；全部完成后还有 1 秒结束静置检查。信号已回落但硬件持续按下会单独报「卡键」，不能确认采用或保存。重测时将提高该键下一轮的阈值下限，而不是把卡键误判成漏触、继续降低阈值。若释放余量与轻触响应无法兼顾，会报告无安全区间。
- 保持面板完全松开；若阈值提高后仍在连续按压时卡键，或基线持续上爬，请检查固件版本、基线追踪与接地/接线，不要靠继续加阈值掩盖硬件问题。

校准不改 DT/DR、SFI/ESI、基线追踪或充放电配置，也不改变固件协议。约 33 Hz 的遥测用于引导采样，**不代表通过了高速连击/游戏延迟验证**。取消、丢弃和正常断开会尝试恢复 RAM 试用配置；恢复无法确认时会阻止保存并提示重连原设备。不要依赖强杀进程来回退。

## 工程结构

- `MaimaiTouchTool/`：Avalonia 主应用程序。
  - `Touch/`：SVG 贴图渲染与按键布局。
  - `Protocol/`：协议 1.1 编解码器与校验。
  - `Transport/`：串口通信、指令队列与超时保护。
  - `Mcp/`：MCP 服务端实现。
  - `ViewModels/`：各功能页面视图模型。
- `MaimaiTouchTool.Tests/`：单元测试。

## 构建与运行

需安装 [.NET 9 SDK](https://dotnet.microsoft.com/download/dotnet/9.0)。

```bash
# 运行
dotnet run --project MaimaiTouchTool/MaimaiTouchTool.csproj

# 测试
dotnet test

# 打包发布 (Windows x64 单文件)
dotnet publish MaimaiTouchTool/MaimaiTouchTool.csproj -c Release -r win-x64 --self-contained false -p:PublishSingleFile=true
```
产物输出至：`MaimaiTouchTool/bin/Release/net9.0/win-x64/publish/MaimaiTouchTool.exe`。
# 实验性防卡键补偿（固件 0.3.0 / 协议 1.2）

配置页最底部提供「实验性功能」总开关：默认关闭，开启后展开「实验性防卡键补偿」设置，可选择「仅观察」或「启用补偿」，并勾选参与按键。
更改设置后点应用；关闭总开关会停用补偿并收起设置，也需应用到设备。再次开启默认进入「仅观察」。保存仅保存模式与选键，运行时阈值仅在 RAM 中。
旧固件仍可连接并正常配置，但不支持此功能时控制项禁用，需升级固件。

算法在持续触摸的稳定高平台后，要求两次相似的「尖峰→快速回落→稳定平台」，才产生候选阈值。
候选有噪声余量、最弱峰上限及最大抬升限制；不叠加抬升，不改硬件阈值/基线寄存器，不按长按超时释放。
仅观察不改任何游戏输出；启用后只对选键使用软件阈值和采样去抖，普通释放不再等平台确认。
学到的状态会在应用、开流、复位或退出会话时清除。原空闲恢复、采样间隔过大或信号无效也会撤销补偿。

「信号曲线」粉色条表示硬件状态，青色条表示最终游戏输出；青色阈值线为候选值。
底部显示候选/生效状态与判别原因；校准验证始终使用原始硬件位，不能靠补偿掩盖失败。
一次只读一个选中电极，目标每键 8 ms；选键较多或 USB 阻塞时实际速率下降，间隔 >40 ms 会丢弃学习。
补偿键的响应受原始采样频率及去抖影响；其余键保留硬件判定。

**仍是实验性启发式**：尖峰不等于证明松手，快速改变长按面积也可能误判；补偿可能断长按或漏轻触。
先测试长按、改变面积、滑动、轻触、连击和多键，再考虑开启。详细数值与存储迁移见 `protocol/PROTOCOL.md`。
