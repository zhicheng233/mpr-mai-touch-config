# AGENTS.md

## What this repo is
Firmware + desktop tool for a maimai (舞萌) touch controller built on 4× MPR121 capacitive touch chips.
- Firmware target: **Seeed XIAO SAMD21 (ATSAMD21G18, ARM Cortex-M0+)**, verified on real hardware. Game input goes out over the USB CDC serial. (Original plan assumed ATmega32U4/Pro Micro; retargeted to the XIAO SAMD21 because that is the board actually in use.)
- Desktop config/debug/test tool: **C# / Avalonia** (modern UI, custom-drawn 34-key touch panel).

## Repo layout
- `maimaiTouchControl/` — existing reference firmware (Arduino sketch, original author HelloworldDk / dkmaiproj). Source of truth for the game-facing serial protocol and the electrode→chip mapping. Kept as reference; new firmware goes in a separate `firmware/` folder.
- `touch/` — SVG textures for the 34 keys (A1–A8, B1–B8, C1–C2, D1–D8, E1–E8). `*_touch.svg` are red "pressed" variants generated by `svg.py` (recolors `fill` → `#871818`). The desktop tool renders these for the live test panel.

## Hardware facts (verified)
- 4× MPR121 on one I2C bus: addresses `0x5A`, `0x5B`, `0x5C`, `0x5D`. Clock 400 kHz.
- 34 keys mapped across the 4 chips in `maimaiTouchControl/config.h` (`touchmap[34]` = `{mprid, portid, thresOffset}`).
- The chip is **MPR121 (12 channels)** — not "mpr212".

## Serial protocol (do NOT break game compatibility)
The maimai game reads this exact format; any rewrite must preserve it.
- **Game mode (default)** streams a 9-byte frame over `Serial`: `(` + 7 bytes + `)`. The 34 touch bits are packed into a 34-bit value and split into 7× 5-bit chunks (LSB first).
- **Commands** are six bytes on the wire, shaped `{xxOx}`; the reference parser stores the first five bytes and checks byte `[3]` as the opcode before the closing `}`:
  - `E` (0x45) RSET — reset/re-init all MPR121
  - `L` (0x4C) HALT — conditioning/standby (stops touch output)
  - `A` (0x41) STAT — start + write per-electrode thresholds
  - `r` (0x72) / `k` (0x6B) — echo ratio/sensitivity

## Decided architecture (from project planning — honor these)
- **Single USB CDC port is reused** between the game and the tool — never both at once. The tool sends an "enter config mode" command; firmware stops streaming and speaks the config/debug protocol until told to exit.
- **Per-board (per-MPR121) + per-electrode config**, persisted using the dual-slot schema in `protocol/PROTOCOL.md`; the tool mirrors it in a local JSON config file (both, per user). Storage backend: on SAMD21 use `FlashStorage` (`FlashAsEEPROM.h`, flash-emulated EEPROM, `EEPROM.commit()` required); on AVR use the real `EEPROM.h` — selected via `#if defined(ARDUINO_ARCH_SAMD)`.
- **Auto-calibration = boot baseline + manual trigger + MPR121 continuous baseline tracking** (combined).
- **Per-electrode thresholds**：芯片寄存器按 per-electrode 阈值写入；映射表决定每个游戏键读哪个板/通道。
- "Better algorithm" = 用 MPR121 硬件触摸状态（`TOUCHSTATUS` 0x00-0x01）判定触摸：硬件内部已按 per-electrode 阈值（寄存器 0x41+/0x42+，由 `applyConfig` 写入 `touchDelta/4`）做触摸/释放检测 + 去抖（DEBOUNCE 寄存器），主机每帧读 4×2 字节即得全部触摸位，响应快（游戏模式主循环 ~几百 fps）。filtered/baseline 仍批量读（filtered 0x04-0x1B 24 字节、baseline 0x1E-0x29 12 字节，走 `Wire.requestFrom` 突发读）用于遥测显示与校准。`baselineData()` 8 位寄存器精度 ×4。注：协议版本字节 = `0x11`（主版本 1 匹配即可，工具按 major 校验），CRC16-CCITT 覆盖 `version+type+seq+len+payload`（从第 2 字节起），不是只对 payload——探针若发错版本字节/CRC 会被固件静默丢弃。
- **可配置按键映射（协议 1.1 / config schema 2）**：某些板子焊接顺序与参考固件不同，同一物理电极在别的固件里可能是另一个键名。映射存在 config blob 的第 34 字节区块：每键一个打包字节 `(board << 4) | channel`（board 0-3、channel 0-11，合法值 0-47），默认值与 `touchmap::Keys` 完全一致，不改就是逐位相同。`electrodeOffsets[34]` 始终是键序（A1…E8），与映射无关；未映射通道用板级值 + 偏移 0。校验要求 34 键的（board, channel）互不重复，否则 `INVALID_VALUE`。blob 长度 59→93，EEPROM 记录 69→103（CRC 位置随之后移，`ReservedStart`=105），旧记录判为无效→载入默认。blob 长度/版本在 `protocol.cpp` 里用 `config::BlobLength`，不要写死。
- **映射编辑器（按板分组）**：工具里映射 UI 是 **4 块 PCB 图形（`Assets/mpr121.svg`）+ 通道列表**，按板分组而不是按键平铺。每块板可单独选 I2C 地址（0x5A–0x5D）；换地址是把两块板**整体对调**（键跟着板走），所以四块板地址永远是双射、不会冲突。通道下拉选一个已在别的通道上的键会**对调**，不丢键；未分配通道在固件里不产生任何游戏键。另有「新建板卡」批量填充（每板键数可编辑，默认 8/9/9/8）、映射撤销/重做（`MappingHistory`，`Ctrl` 按钮）、以及映射快照（`MappingSnapshotStore`，Apply/Save 时写入 `%APPDATA%\MaimaiTouchTool\mapping_snapshots.json`，可一键回滚）。映射自动学习按**板序**（板 1→4、通道 0→11）提示，无需事先知道映射。**零协议改动**：blob/`keyMap` 打包/游戏帧/`electrodeOffsets` 键序/EEPROM 全部不变。
- **SVG 渲染**：`SvgPathConverter` 必须返回 `SvgImage`（不是裸 `SvgSource`）才能绑到 `Image.Source`；PCB 面板用 `Viewbox`+`ClipToBounds` 只裁出 SVG 底部电极区。通道槽位坐标来自 `mpr121.svg` 的焊盘位置（`x = 55 + 50·ch`、`y = 385`）。
- **调试流实际速率**：请求 100 Hz，实际受 USB CDC 突发写 + I2C 批量读限制约 33 Hz（改进后；早期软件检测只有 11.3 Hz）。100 Hz 与 207 字节帧在 115200 名义波特下不可兼得。
- **"Sensitivity" model** = two axes: (a) threshold level (baseline-derived, per-board base + per-electrode signed offset) and (b) response speed (touch/release debounce + SFI/ESI sampling). Both exposed in the tool and runtime-writable.
- **Config/debug protocol**: use `protocol/PROTOCOL.md` as the byte-level source of truth (binary `0xAA 0x55` framing with version/type/seq/len/CRC); debug stream = 100 Hz default.
- **Firmware build**: PlatformIO, env `seeed_xiao` (atmelsam; Seeed XIAO SAMD21). New firmware lives in `firmware/`; `maimaiTouchControl/` stays as untouched reference.

## Build / flash / commands
- Reference firmware (`maimaiTouchControl/`) is an Arduino `.ino` — build via Arduino IDE (Leonardo board) or `arduino-cli`.
- New firmware: PlatformIO `pio run -e seeed_xiao` (build); artifact `.pio/build/seeed_xiao/firmware.bin`.
- **Flashing the XIAO SAMD21** (learned the hard way): the board has an Arduino SAMD bootloader (bossac), NOT UF2, despite the `INFO_UF2.TXT` on the drive. The bootloader lives on a NEW COM port, not the application's port. `pio run -t upload` frequently hangs because its 1200bps touch auto-reset only works ~50% of the time. Reliable sequence:
  1. `cmd /c "mode COMx: BAUD=1200"` on the application COM port (or double-tap RST) to reset into the bootloader.
  2. Note the NEW COM port that appears (the bootloader port; the app COM disappears).
  3. `bossac --port=COM<boot> -U true -e -w -v -R <firmware.bin>` (bossac at `~/.platformio/packages/tool-bossac/bossac.exe`). `-U true` is required.
  4. It boots the app: back on the application COM port, PID `0x802F`.
- **1200bps touch 的真实条件**（核心 `cores/arduino/USB/CDC.cpp` 决定，不是约定俗成）：`baud == 1200 && (lineState & CDC_LINESTATE_DTR) == 0` → `initiateReset(250)`，否则 `cancelReset()`。**DTR 必须是低的**。之前写 `DtrEnable = true`，驱动会在设置波特率后再拉起 DTR，正好取消掉已排上的复位，表现就是「偶尔刷得动」。正确做法：打开 1200 波特时 `DtrEnable = false`，停留约 500 ms 再关闭。实测第一轮仍有一半概率不生效，**必须允许重试**（4 次足够，单轮等 2 s）。
- **找 bootloader / 应用口不要靠端口集合差集**：注册表 `HKLM\SYSTEM\CurrentControlSet\Enum\USB\VID_2886&PID_002F&MI_00\...\Device Parameters\PortName` 有 PID→COM 的映射（bootloader `0x002F`、应用 `0x802F`、VID `0x2886`）。但注册表**保留已拔掉设备的历史键**，必须与 `SerialPort.GetPortNames()` 求交集，否则会对着不存在的口跑 bossac（只报 `exit code 1`）。差集法的另一个坑：板子已经在 bootloader 里时，它的口已在上一次快照中，重试会永远找不到。
- **应用内刷写**：`Firmware/FirmwareFlasher.cs` 全自动跑完「释放串口 → 1200bps 复位 → bossac 擦写校验复位 → 找回应用口」，界面在「固件」标签页（`FirmwareViewModel`）。不用 `pio run -t upload`。`firmware/src/version.h` 是固件版本号唯一来源，`firmware/extra_script.py` 在构建后生成 `firmware.json`，csproj 把 `firmware.bin` + `firmware.json` 拷到输出目录 `Firmware/`。
- The board's application CDC **resets on serial-port open** (DTR) then runs a ~1 s boot calibration, so a fresh open has no output for ~1 s before the 9-byte game frames start. Do not read immediately after opening.
- Tool: `dotnet build` / `dotnet run` (Avalonia, .NET 8).
- **MCP 服务器（两种入口，同一套工具）**：工具定义与分发在 `Mcp/McpToolHost.cs`，背后是一个 `IMcpSession`；`McpServer.cs` 只做 JSON-RPC 分发。暴露 `connect/disconnect/get_config/set_board/set_electrode/set_mapping/apply/save/calibrate/read_telemetry` 共 10 个工具，接入教程见 `Mcp/README.md`。
  - **stdio 入口**：`MaimaiTouchTool.exe --mcp` 用 `StandaloneSession`（自建 `SerialTransport` + `ConfigurationWorkflow`，无 GUI），stdout 只写 JSON-RPC（newline-delimited），可被客户端 spawn 并管道重定向（已实测，`OutputType=WinExe` 不影响）。
  - **GUI 内嵌入口（推荐）**：界面「AI / MCP」标签页点启动，`McpHttpHost` 在 `127.0.0.1` 起最小 HTTP（MCP Streamable HTTP，JSON 响应），用 `GuiSession` 直接操作运行中的 `MainViewModel`，与界面共用同一条串口 —— 所以「不用关程序」。默认端口 8477，被占时向后顺延，实际端口回填到 `McpGuide.Endpoint`（状态行/片段/自检脚本都跟着变）。
  - **真正互斥的是「同一个 COM 口被两个程序打开」，不是「程序开着」**：GUI 只在 `ConnectAsync` 里打开串口，断开即释放。所以 `--mcp` 独立进程只需让 GUI **断开连接**，不必关程序。UI 警告和 README 都已按这个说法改写，别再写成「必须关闭程序」。
  - `GuiSession` 的每个调用都必须切到 UI 线程（`Dispatcher.UIThread`）：编辑器模型绑定到界面，从 HTTP 线程改属性会抛 `Call from invalid thread`。异步调用要用 `TaskCompletionSource` 包一层，不能直接 `await InvokeAsync(async () => ...)`（那是 async void，第一个 await 就返回了）。
  - 回环 HTTP 三层防护：只绑 `IPAddress.Loopback`；拒绝带 `Origin` 的请求（浏览器跨域必带）；只接受 `Content-Type: application/json`（浏览器发它会先预检，而 OPTIONS 直接拒）。
  - `set_mapping` 暂存某键的板号(1-4)/通道(0-11)；目标通道已占用时默认报错，`swap=true` 则两键对调（`Mcp/McpMapping.cs` 是唯一实现，stdio 与 GUI 共用）。**占用者必须在赋值前查找**，赋值后再搜会先搜到刚改的那个键自己，对调就变成「和自己对调」。
  - `get_config` 在未 connect 时报错（早期版本会静默返回默认配置，是 bug）；`set_board` 除 `board` 外全部可选，未传字段保持原值。GUI 模式下 `get_config` 返回**已应用**配置，`set_*` 改的是界面暂存区（会显示「未应用」）。
- **GUI 里的 MCP 引导页**（`Tab.Mcp` = "AI / MCP"）：`McpGuideModel` 生成启动命令、内嵌端点的 JSON 片段（OpenCode remote / mcpServers http）与独立进程的三种片段（OpenCode / Claude Desktop / Cursor）、自检脚本，exe 路径取自 `Environment.ProcessPath` 并自动转义成 `\\`。工具清单直接读 `McpToolHost.Describe()`，**不要在界面里手抄工具名**；每个工具的说明走 `Mcp.Tool.{name}` 本地化键，缺键时回退到 MCP 定义里的原文。客户端下拉框标签也走本地化（`Mcp.Client*`），不要硬编码成 `"OpenCode · embedded"` 这种英文。
- Serial I/O gotcha: `SerialPort.BaseStream.ReadAsync/WriteAsync` does **not** reliably honor a `CancellationToken` (hangs forever on a quiet/open port). The transport therefore loops synchronous `SerialPort.Read` (bounded by `ReadTimeout`) on the thread pool, and cancels by calling `Abort()` (which closes the port). Per-command timeouts must **not** tear down the port (they throw `TimeoutException`, port stays usable); only explicit user cancel / disconnect calls `Abort()`.
- Device-state gotcha: the firmware returns `AlreadyConfigured` for ENTER_CFG if it's already in config mode (e.g. after the tool was force-killed), and rejects GET_CFG with `Busy` while STREAMING. The tool tolerates both (ENTER_CFG already-configured = success; on Busy it sends STREAM_STOP then retries GET_CFG). Force-killing the tool leaves the board in config mode until EXIT_CFG or the firmware's ~30 s idle timeout.
- Debug logging: set `MAIMAI_SERIAL_LOG=1` to write serial send/receive + request/response lines to `%TEMP%\maimai_serial.log`.
- `protocol/PROTOCOL.md` is the single source of truth for the firmware↔tool protocol.

## Desktop tool i18n (multi-language)
- Localization lives in `software/MaimaiTouchTool/Localization/Localizer.cs`: a singleton `Localizer.Instance` holding `en` + `zh-Hans` string tables. Add new UI text here (both dictionaries) — never hardcode English in XAML or code.
- **XAML**: use `{DynamicResource Key}` (NOT `{Binding [Key], Source=...}` — indexer bindings do not refresh at runtime). The keys come from `Localizer.Instance.Resources`, which is merged into `Application.Resources` in `App.Initialize`. Switching language mutates that dictionary in place, so `DynamicResource` references update live.
- **Code (ViewModels/models)**: read strings via `Localizer.Instance["Key"]`. Properties computed from strings must re-raise `OnPropertyChanged` on `Localizer.Instance.LanguageChanged` (see `MainViewModel.RaiseLocalized`, `TelemetryModels`).
- `RebuildResources()` clears `Resources` before repopulating. It did not originally, which left keys from the previous language in the dictionary forever — removing a key from the new table would still render the stale text. `McpGuideTests.BothLanguageTablesDefineTheSameKeys` guards that both tables stay in sync.
- **Tests**: `MaimaiTouchTool.Tests/AssemblyInfo.cs` sets `DisableTestParallelization = true`. `Localizer` is a process-wide mutable singleton, and several tests assert literal English strings ("Board 1 (0x5A)"), so any test that calls `SetLanguage` races with them otherwise. Keep that setting; new localization tests should restore `en` in a `finally`.
- Language is switched by the header ComboBox (`SelectedLabel` → `SetLanguage`). Startup language can be forced with env var `MAIMAI_LANG` (e.g. `zh-Hans`).
- Static-init gotcha: static field initializers run in textual order — `Localizer.Instance` is declared last (after `Available`/`En`/`Zh`) precisely to avoid constructing before the tables exist.
